# 28-11-2026

[← Back to changelog index](../CHANGELOG.md)

## Entries

- [Added] Antigravity integration through `anchor init-antigravity` and combined `anchor init`, registering flat lifecycle handlers (`SessionStart`, `Stop`, and opt-in `PreInvocation`) under the `"memory-anchor"` named group in `.agents/hooks.json` while preserving unrelated named hooks, user handlers, and any explicit `"enabled": false` setting.
- [Added] Workspace-scoped Antigravity MCP registration via `.agents/plugins/memory-anchor/plugin.json` and `.agents/plugins/memory-anchor/mcp_config.json`, binding `--workspace` per repository without modifying global `~/.gemini/config/mcp_config.json` and preserving custom manifests and existing server entries.
- [Added] Antigravity hook handlers (`memoryanchor-antigravity-pre`, `memoryanchor-antigravity-prompt`, `memoryanchor-antigravity-stop`) with camelCase stdin workspace resolution (`cwd`, `workspacePaths`, and `.agents/` fallback), `injectSteps` (`systemMessage`) context replies, opt-in `PreInvocation` reminders (`anchor prompt-hook antigravity` / `agy`), and `Stop` incremental chart refresh returning `{"decision":"allow"}` after releasing parser workers.
- [Updated] `GITIGNORE_ENTRY`, `hookProtocol.ts`, `hookDebug.ts`, `README.md`, and `.memoryanchor` state/decisions docs for Antigravity (`AGENTS.md` is read natively, so no separate `GEMINI.md` is generated).
- [Tested] Added `tests/init/init-antigravity.test.ts` and `tests/hooks/antigravity-hooks.test.ts` and updated MCP and prompt-hook suites; full `npm test` passes build, type checks, and 297 tests across 44 active suites.
- [Added] MCP `get_memory` and `write_memory` tools backed by `src/mcp/memoryStore.ts`: read a memory directory, every entry of one kind, or one entry, and add/update/remove guardrails, decisions and project-state modules (field-level patches) with content-derived ids, optional module version checks, similar-entry detection with `force`, a cross-process lock, atomic rename and advisory budget warnings. Markdown remains the only store and hand edits stay supported.
- [Updated] `AGENTS.md` template, MCP usage guidance and the project-state directory hint now recommend `get_memory`/`write_memory`; new `.mcp.json` registrations list all five tools. `projectStateModules` now derives from a line-range parser shared with writes.
- [Tested] Added `tests/mcp/memoryStore.test.ts` (in-place edits, fences, CRLF, symlink refusal, concurrent writers, stdio calls); including four separate MCP server processes writing concurrently without losing entries or field updates; full `npm test` passes 308 tests across 45 active suites.
- [Changed] Every `anchor init` / `init-<agent>` now refreshes an existing `memory-anchor` MCP entry that Memory Anchor wrote (`<node> .../dist/cli.js mcp ...`) to the running installation in `.mcp.json`, `opencode.json`, Codex TOML (line-in-place, comments kept; unsupported layouts are left with a warning), Hermes YAML, Qwen Code, ZCode, Antigravity and the DeepSeek overlay. Paths are compared by real path so symlinked spellings do not churn; legacy default `tools` lists gain the new tools while custom lists, user-owned launches, other entry keys and client trust policies are preserved.
- [Changed] Rewrote the generated `AGENTS.md` block around MCP: tools, memory kinds (guardrails / decisions / project_state) instead of file paths, chart notation and workflow. It assumes MCP is available, drops every fallback instruction and the guardrails format section, and ends with a single warning that editing `.memoryanchor` files directly is undefined behaviour because it bypasses the write lock. MCP usage guidance follows the same rules.
- [Changed] `write_memory` accepts plain language: it collapses newlines in guardrails, module names and fields, strips list/checkbox/heading markers the caller added, and applies the storage format itself instead of rejecting multi-line input.
- [Added] MCP `recall_memory({query, kind?, limit?})`: ranks guardrails, decisions and project-state modules against a keyword query with Okapi BM25 (k1 1.2, b 0.75, Lucene idf) and returns the best complete entries with their kind, id, score and module version, so they feed `get_memory`/`write_memory` directly. Each call rereads the markdown files, so hand edits and other writers are always seen, and reuses a per-process tokenized index while their content is byte-identical (about 0.3 ms per call instead of 4.5 ms for this repository's 60 entries); nothing is persisted, so the index cannot go stale.
- [Added] `src/mcp/bm25.ts`: a tokenizer for prose, code identifiers and CJK text (NFKC, camelCase/PascalCase/acronym/snake_case splitting that keeps the compound, a small stop-word list, light plural/-ed/-ing stemming, CJK character bigrams) and a reusable `Bm25Index` that scores every document, ready to be fused with embedding similarity later.
- [Changed] `MCP_TOOL_NAMES`, MCP usage guidance, the generated `AGENTS.md` block and `README.md` include `recall_memory`; re-running init upgrades managed registrations that still list a previous default tools list.
- [Removed] MCP `get_project_state` (and `ChartReader.getProjectState`): `get_memory({kind: "project_state"})` lists modules with versions and status and `get_memory({kind: "project_state", id})` reads one, so the tool only duplicated it. New registrations list `get_chart`, `get_file`, `get_memory`, `recall_memory` and `write_memory`; re-running init rewrites managed default lists that still name `get_project_state`, while custom lists are kept.
- [Changed] Init migrates a `project-state.md` without modules, which memory tools cannot address: it dedents the indented Module Status manifest template so its modules and Key Decisions are recognized (decisions still split into `decisions.md`), replaces the empty pre-module `## Todo:` / `## Done:` manifest default with the current default, and moves any other module-less text verbatim, indented four spaces so its headings and fences stay inert, into one `Legacy project state` module whose status asks agents to split it. Structured files, heading-only files and files with any module are untouched, and the migration is idempotent.
- [Changed] Session context no longer injects an unreadable `(whole document)` module for module-less project state; instead the memory maintenance notice asks to run `anchor init`.
- [Tested] Added `tests/mcp/memoryRecall.test.ts` (stemming, identifier and CJK terms, BM25 idf/saturation/length normalization/ties, cross-kind recall, kind filter, limits, duplicates, fresh reads after writes, input errors, content-keyed cache reuse) and project-state migration tests in `tests/init/init-public.test.ts` (verbatim legacy module read back through `get_memory`/`recall_memory`, idempotent re-init, dedented manifest template, untouched structured/heading-only/CRLF content); moved the project-state read assertions from `get_project_state` to `get_memory` and updated stdio, session-context and init discovery suites. Full `npm test` passes build, type checks and 322 tests across 46 active suites.
